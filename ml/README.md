# SiteSuri ML

The location opportunity score from `model_architecture_v2.md` (revision 2): an XGBoost pedestrian
model plus rule-based business fit, competition, walkability and safety components, combined with a
gated geometric mean, hard caps and hazard flags.

> **Prototype, synthetic data.** The model is trained on generated data, so scores show how the
> pipeline behaves, not conditions at real places. All weights and thresholds are uncalibrated placeholders.

## Layout

```text
ml/
├── sitesuri_ml/
│   ├── __init__.py
│   ├── config.py       # parameters, synthetic-data profiles, constants
│   ├── synthetic.py    # generate the synthetic datasets
│   ├── features.py     # load/check input tables, scoring-time feature grid, features for a searched point
│   ├── pedestrian.py   # XGBoost model, expected pedestrians per hour, 0-100 scaling
│   ├── validation.py   # metrics, holdout evaluation, planted-effect checks, sensitivity test, spec checks
│   ├── scoring.py      # business fit, competition, walkability, safety, aggregation, output records
│   ├── pipeline.py     # training orchestration (TrainOptions, run)
│   ├── inference.py    # ScoringService: the interface used by FastAPI
│   └── geocode.py      # Nominatim search and reverse geocoding, rate limited
├── tests/
├── artifacts/          # trained model + everything inference loads (committed)
├── examples/fastapi_endpoint.py   # example endpoints for apps/api
├── data/               # synthetic training data (git-ignored, regenerated by training)
├── train.py            # CLI entry point
├── requirements.txt
└── pyproject.toml      # lets the API install this folder: pip install -e ../../ml
```

Dependencies only point one way: `config` ← `synthetic`, `features` ← `pedestrian`, `scoring` ←
`validation` ← `pipeline`; `inference` uses `config`, `features`, `pedestrian` and `scoring` only.

## Setup (Linux)

```bash
cd ml
sudo apt install python3-venv        # Debian/Ubuntu/Mint, if venv is missing
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,api]"       # or: pip install -r requirements.txt
```

## Commands

```bash
python train.py selftest          # score formulas vs the spec's worked examples
python train.py generate          # synthetic tables only -> data/synthetic/
python train.py run               # retrain (~20 s) -> artifacts/; --help lists every option
pytest                            # 52 tests
python -m sitesuri_ml.inference --lat 14.6508 --lon 121.03 --business-type "sari-sari store"
```

Training can also be called from Python: `from sitesuri_ml import TrainOptions; from sitesuri_ml.pipeline import run; run(TrainOptions(skip_sensitivity=True))`.

`run` writes to `artifacts/`:

| File | Used for |
|---|---|
| `pedestrian_model.json` | trained XGBoost model |
| `scoring_config.json` | scaling bounds, range ratios, parameters, default schedule |
| `locations.csv` | location features inference looks up |
| `rain_climatology.csv` | average rain by month and hour, used when scoring |
| `scores.json` | precomputed scores for every site and business type |
| `validation_report.json`, `sensitivity*.{json,csv}` | model quality and parameter sensitivity reports |

## Using it from the FastAPI backend

Install the package into the API's environment (from `apps/api`): `pip install -e ../../ml`.

```python
from sitesuri_ml import ScoringService, OutsideCoverageError, UnknownBusinessTypeError

service = ScoringService()   # create once at startup; loading takes about a second

record = service.score(
    14.6508, 121.0300, "sari-sari store",
    open_hours=(8, 20),          # optional, 06:00-22:00 range
    open_days=range(7),          # optional, 0 = Monday
    location_label="…",          # optional, e.g. the Nominatim display name
)
```

- Errors: `UnknownBusinessTypeError` → 422, `OutsideCoverageError` (no data within 500 m) → 404, other `ValueError` → 422.
- `service.business_types` lists the valid business types: food stall, sari-sari store, general retail.
- The record follows spec §8.4: `location_score`, `weakest_component`, `flags`, `caps_applied`,
  `components` (with details), `info_only`, plus `matched_site`, `schedule`, `notice` and `disclaimer`.
- `examples/fastapi_endpoint.py` shows `/map/score`, `/map/search`, `/map/business-types` and `/map/sample-sites`:
  `uvicorn examples.fastapi_endpoint:app --reload`, then open http://127.0.0.1:8000/docs.

## Seeing it in the web UI

`apps/web/src/app/score/` is a page that calls the API from the browser. Run both servers:

```bash
# terminal 1, from ml/ with the venv active
uvicorn examples.fastapi_endpoint:app --reload          # http://127.0.0.1:8000
# terminal 2, from apps/web
npm run dev                                             # http://localhost:3000/score
```

The API allows browser calls from `localhost:3000` (CORS; change with `SITESURI_CORS_ORIGINS`). The page
reads the API address from `NEXT_PUBLIC_ML_API_URL` (default `http://127.0.0.1:8000`).

## Geocoding (Nominatim)

```python
from sitesuri_ml import NominatimClient
geocoder = NominatimClient("SiteSuri/0.1 (team-email@example.com)")
geocoder.search("Cubao")             # search box -> candidates (Philippines only)
geocoder.reverse(14.6508, 121.03)    # map click -> address
```

The public server's policy: at most 1 request/second (enforced by the client), a User-Agent that identifies
the app, no bulk or scheduled geocoding, and "© OpenStreetMap contributors" shown wherever results appear
(each result has an `attribution` field). Don't log or store what users type into the search box.

## How a searched point gets its features

`NearestSiteProvider` matches the point to the nearest site in `artifacts/locations.csv` (within 500 m)
and scores that site's features, which is the matching rule spec §11 item 7 calls for. The synthetic
sites cover parts of Manila and Quezon City (around 14.57–14.69 N, 120.98–121.07 E).

To move to real data, write a provider with the same `lookup(lat, lon) -> (site_dict, match_dict)`
method that builds the fields in `features.REQUIRED_SITE_FIELDS` from OSM / PostGIS / hazard layers, and pass
it in: `ScoringService(provider=MyProvider())`. Then retrain with real counts:
`python train.py run --training-csv … --locations-csv … --rain-climatology-csv …`.
